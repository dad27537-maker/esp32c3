## 测试边界

菜单和番茄钟自动检查通过串口调用与实体按键相同的业务处理函数，不替代对五个机械方向接线的人工观察。当前GPIO沿用用户在本地调整后的board_config.h，本次没有按旧原理图默认值覆盖。

截图是实物执行固件绘制的画面，不是光学拍摄；面板自身的背光亮度、观察角度和色彩仍以实物为准。图片总览是整数倍放大，未替换成概念设计图。

硬件传感器读不到时返回null，板端显示“--”。CPU温度和非NVIDIA显卡可通过可选的本机LibreHardwareMonitor Web Server补充；当前机器未启用该接口，因此没有声称CPU温度已验证。

NTP已配置为非阻塞网络校时，当前时钟画面与电脑时间一致；没有单独断开电脑接收程序来证明本次校时具体来自哪一路。校时后，板端系统时钟独立运行；断电重启需要重新校时。

真实快捷键测试仅对自己创建的临时窗口发送Ctrl+C，并由窗口拦截，不对用户原先选中的窗口主动执行复制。用户仍需在目标软件中通过“选中 → 上键 → 粘贴”确认该软件自身的行为。

真实媒体键检查证明接收程序能够向Windows注入3组标准媒体键，不证明任意播放器都会响应。测试钩子只识别并拦截注入的3种媒体键，其他输入直接传递且不记录，结束后移除钩子。播放器需要支持系统媒体键；本次没有主动切换用户播放器的曲目或播放状态。

新增媒体键、复制粘贴都只在按下边沿发送一次；媒体页上下键没有菜单和音量页的自动连发。

## 解决过的问题

- 早期屏幕初始化反复重启：TFT_eSPI将逻辑SPI2_HOST编号1传入只识别物理编号2的SDK寄存器宏。include/esp32c3_tft_compat.h针对该SDK定义做兼容映射，并保留编译期断言。
- 一次编译出现SDK连带错误：兼容头文件中的提示字符串被截断，已修复并在VS Code同一PlatformIO环境编译通过。
- 早期复制请求到达电脑却无效：受限后台进程调用SendInput返回0/4、Windows error 5。已停止旧进程，在正常交互Windows环境启动接收程序，真实输入检查通过。新版板端能单独显示“权限受限”。
- 早期中文标题缺笔画：原字模从GDI绘制结果固定截取12×12，部分笔画超出截取边界。新版完整取字后生成10×10子集，适配小屏。

本地include/secrets.h和pc/receiver_config.json包含运行配置，已由.gitignore排除；本文不记录WiFi密码和API令牌。
